# FFOne Studio

Откройте [Open Dashboard.cmd](../../Tools/Studio/Open%20Dashboard.cmd). Дашборд запускается на компьютере разработчика и открывается в браузере. Повторный запуск открывает уже работающий экземпляр. Архитектура открывается в отдельном окне. Для запуска в терминале из корня проекта:

```powershell
python Tools/Studio/dashboard.py serve --open
```

## Очереди и диаграммы

Источник начального плана — [снимок листов «Баги» и «Вишлист»](ffoneclient-unity-triage-2026-11-18.md). При запуске 18 ноября 2026 сверены координаты и тексты всех 531 записей с Google Sheets. Снимок содержит 433 замечания о багах и 98 предложений, включая 10 QoL. Счётчики показывают карточки, среди которых встречаются повторы исторических сообщений. У каждой импортированной записи есть ссылка на ячейку.

Статус работы независим от степени проверки. «Частичный прогон» означает проверку части симптома на конкретной сборке или в серверном тесте. Историческое закрытие в FFOneClient сохраняется отдельно. Сводка исследований использует реестр provenance.json. Прогресс фич считается относительно заведённых предложений.

Карточки сохраняются в Git-совместимых JSON в `Docs/Studio/dashboard/cards`. Исходные записи и пользовательские изменения объединяются по ID. Локальные изменения видны после обновления страницы и при автоматическом опросе. Изменения карточки записываются атомарно с историей полей. Исходная таблица служит снимком для импорта, запись обратно в Google Sheets не производится.

## Рабочий цикл агента

Диаграмма багов использует тематический столбец исходной таблицы. Для общих колонок «Открыто» и «Закрыто» начальная подсистема предложена по словам в замечании. Спорное назначение можно изменить в карточке. Нажмите полосу, чтобы увидеть список, из которого рассчитано число.

Для каждой проектной задачи интегратор ведёт одну карточку. Если ID уже указан в запросе, откройте её. Если задача пришла отдельно, поищите существующую запись и создайте новую только при необходимости.

```powershell
python Tools/Studio/dashboard.py list --search "портрет"
python Tools/Studio/dashboard.py create --kind task --title "Проверить первый кадр ростера" --area "Персонажи" --status active
python Tools/Studio/dashboard.py get bugs-C58
```

Перед итоговым ответом обновите запись по ID фактической задачи. Команда работает и при закрытом дашборде. Поля, которые вы не передали, сохраняются. Перед изменением заметок прочитайте последнюю версию карточки. Предыдущие значения обновлявшихся полей доступны в истории изменений.

```powershell
python Tools/Studio/dashboard.py update ID --status review --verification tested --evidence "Сборка, сценарий, результат и путь к протоколу" --notes "Что осталось проверить"
```

Для завершённой задачи укажите `done` и результат проверки. Для уточнения используйте `clarify` и конкретный вопрос, для задачи с готовой постановкой — `ready`. У подтверждённого дефекта степень проверки `confirmed`, у успешно пройденного полного сценария — `passed`. У новых карточек записывайте день выполнения, версию сборки и масштаб теста в evidence, если это влияет на интерпретацию.

Кнопка разбора запускает Codex с правилами проектной роли `bug_triage_analyst`. Аналитик может разделить список замечаний, связать дубли и сохранить вопрос автору. Кнопка разработки запускает отдельный чат этой карточки. Требуются доступный локальный Codex CLI, настроенный вход и приложение с обработчиком ссылок Codex. Повторное открытие использует сохранённый ID соответствующего чата.
