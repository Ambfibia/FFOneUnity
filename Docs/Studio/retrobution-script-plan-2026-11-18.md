# Retrobution → FFOneUnity. План по скриптам на 18 ноября 2026

Первой задачей предлагаю **смену оружия в мире**. В настройках Unity уже есть эта команда, у RustyFusion есть транзакция для обоих слотов, а FFOneClient задаёт точные правила их обмена. Следующие самостоятельные задачи — видимый Nano рядом с игроком, боевой прицел и мастерская внешности у NPC.

## Очередь реализации и приёмка

Две детали из тел методов задают границы первых задач. В `WeaponChange` видны оба направления обмена между слотами 0 и 7 и отправка `0x1300000A`. В `cnAvatarAttack.MakeBullet(Transform)` (`0x060000d4`) выбирается перегрузка `AvatarUtil.MakeBullet` с целью либо с координатой. Имя `drawCrosshair` взято из комментария Unity. Его принадлежность конкретному методу старой DLL и точное условие показа пока не установлены.

Использовать существующий запрос перемещения и ответ сервера. Проверить ограничения ввода при открытом окне, в транспорте и во время предыдущего запроса. | Два разных оружия меняются местами. Одно оружие можно убрать и вернуть. При пустых слотах или отказе содержимое сохраняется. Следующая атака, модель в руке, вид у второго клиента и состояние после повторного входа согласуются. Исследовать параметры следования по выбранному типу. Использовать существующий каталог моделей и асинхронную загрузку. | Два клиента видят одного и того же спутника у правильного владельца. Для изменений загрузки аватаров сохранить первый видимый кадр, занятые портреты, создание и вход в мир. [Процедура проверки](validation.md)

Для оружия и инстансов есть отдельные исторические прогоны. Точность физики гранаты и отдельные эффекты остаются отдельными вопросами. В Unity имеются игровые точки входа, сетевые вызовы и обработчики состояния для этих семейств. Для следующей сверки выбрать один сценарий на семью, например завершение задания с сопровождением и наградой или обмен с разрывом связи между подтверждениями. ## Основание и пределы сверки

Исследован рабочий срез FFOneUnity поверх `f5b40dbc`, включая локальные правки. Базовые ревизии FFOneClient `fdee0fb8`, RustyFusion `718e92de`, FusionForge `6da75fe1`. Посмотрели управляемые методы одного первичного контейнера и сопоставили выбранные игровые пути с исходниками трёх проектов. Это выборка по системам. Полный список расхождений каждого метода, сцен и сериализованных привязок остаётся открытым.

Источник старого кода — `builds/retrobution-20260821/main.unity3d`, SHA-256 `01b544976b2d54355507cf30fe6dfada2b476b92b209a3d47c1499669ed9b4ef`, вложенная `Assembly - CSharp.dll`. Токены выше относятся к этой сборке. Использованный исполняемый файл FusionForge имеет SHA-256 `013358c4b5264c459ca897ace41f53faad64dc4ca53091df01843f35c1489208`.
