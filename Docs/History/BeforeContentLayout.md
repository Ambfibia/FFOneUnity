# FFOne Unity

Перенос Retrobution 20260821 на Unity 6000.4.0f1 / URP 17.4 / UI Toolkit.
Это ещё не завершённый клон 1:1 и не production release: границы переноса
и непроверенные сценарии перечислены ниже.

Откройте проект в Unity, затем **FFOne → Open Client** и нажмите Play.
Сцена запуска: `Assets/Scenes/Main.unity`.

Контент находится непосредственно в `Assets/Resources`, скрипты — в
`Assets/Scripts/Runtime` и `Assets/Scripts/Editor`, шейдеры — в `Assets/Shaders`.
Стандартные TutorialInfo, Readme и SampleScene удалены.

## Окружение и растительность

**FFOne → Environment → Environment Library** открывает библиотеку окружения с
категориями, поиском, миниатюрами и перетаскиванием prefab в сцену. Каталог включает
только исходные `objects/`: мобы, фьюжены, уникальные NPC, Nano и HNPC остаются
в системе персонажей/XDT. HNPC используют базу аватара игрока. Их расстановка
требует отдельного редактора серверных ID и координат.

Опубликованное окружение расположено в `Assets/Resources/Environment/<категория>`.
Исходные GLB сохраняют свои прежние пути; опубликованные prefab, меши, материалы
и клипы перемещаются с прежними GUID. Каталоги загрузки и метаданные публикации
обновляются вместе с переносом. `Resources` пока нужен действующему загрузчику;
переход на Addressables в этот этап не входит. Категории, предложенные по исходным
именам, можно исправлять в браузере; `Review/Unclassified` требует ручной проверки.
Технические коллизии скрыты в общем списке по умолчанию. Отдельный импортированный
prefab может представлять часть конструкции, а не целое здание.

**Open Terrain Editing Cell** открывает список 170 ячеек. Для выбранной ячейки
создаётся сцена в `Assets/FFOne/Worlds/Overworld/Cells` с окружением в исходных
координатах. Повторное открытие сохраняет авторские изменения. Это редакторские
сцены; игровой WorldStreamer пока продолжает читать WorldTileContent, поэтому
сохранённая расстановка этой сцены ещё не публикуется автоматически в runtime.

**Import Compatible Terrain Details** переносит исходные карты плотности травы
в TerrainData совместимых тайлов. Поверхность и материалы земли остаются мешами;
Terrain рисует только растительность (`drawHeightmap=false`). Его TerrainCollider
нужен кистям редактора и отключается в Play Mode, где работает исходный MeshCollider.
Сохраняются клетки и количества Details; распределение отдельных травинок внутри
клеток рассчитывает Unity. Тайлы со сдвигами вершин продолжают использовать прежнюю
растительность. Повторный импорт не перезаписывает уже отредактированный TerrainData.
Редакторская сцена получает собственный TerrainData: изменение её дерева экземпляров
не создаёт дубли деревьев в пока ещё отдельном игровом стримере.

**Convert Selected Trees To Terrain Trees** работает с выбранным Terrain Vegetation
и корнями экземпляров деревьев из библиотеки в той же редакторской сцене. Перенос
сохраняет X/Y/Z, поворот вокруг Y и масштаб без прилипания к высоте Terrain; имеет Undo.
Наклонённые деревья, несовместимый масштаб, дополнительные компоненты/коллизии,
изменённая геометрия и составные модели отклоняются. Старые модели с другой системой
осей требуют отдельной нормализации; их нельзя массово выпрямлять по имени файла.

Для 4 236 статических GLB окружения подтверждённая размещениями ось Z-up запечена
в вершины, нормали и касательные как Y-up. GUID опубликованных мешей и prefab сохранены.
Маркер `ffoneAuthoringBasis` в GLB делает повторную операцию идемпотентной; импорт
из FFOneClient сохраняет эти локальные версии. `WorldModelBasis` компенсирует новую
геометрию только при старом размещении мира: исходные TRS, коллизии и поведенческие
анимации продолжают использовать свою систему координат. В библиотеке модель имеет
правильную ориентацию без поворота корня. Уже Y-up и неоднозначные модели не преобразованы.
`Tools/validate_environment_basis.py` сравнивает все преобразованные GLB с независимым
набором FFOneClient, включая неизменённые бинарные данные и материалы.
В опубликованных NativeWorld-материалах исправлена старая маска каналов `7` на Unity RGB
(`14`); исходные режимы прозрачности, текстуры и цвета сохранены.

Экран входа описан в `Assets/Resources/ui/views/Login.uxml` и доступен в UI Builder.
Общий стиль всех кнопок и полей — `ui/styles/FFTheme.uss`; оформление экранов —
`ui/styles/Frontend.uss`. Общие состояния кнопок и таблица sliced-границ находятся
в `Scripts/Runtime/UI/Common`; login, selection, dialogs и browser имеют отдельные
файлы привязок. Выбор персонажа и динамические части конструктора пока строятся
из кода через эти общие компоненты.

UI-графика импортируется как Sprite / Full Rect с исходными border, без компрессии
и mipmaps. Шрифты TextCore SDF созданы из согласованных `jeffe.otf`
(RussianRail G Pro), Chalet и Comic Sans; TextMeshPro здесь не требуется.
Верхний регистр применяется к подписям FF, но не к вводимым данным.

Windows development client собирается через **FFOne → Development → Build Windows Client**
в `Builds/Windows/FFOne.exe`. Существующая сборка от 2026-10-13 00:26 предшествует
полной публикации контента; для включения новых assets её нужно пересобрать.
Её успешный Build Report находится в `Logs/MigrationWindowsBuild.log`,
размер по Unity — около 7,3 ГБ.
Для переноса сборки копируйте всю папку `Builds/Windows`, включая
`FFOne_Data`, `MonoBleedingEdge` и DLL. Сборки исключены из Git.

В этом срезе доступны вход через ofapi или напрямую в RustyFusion, четыре
слота персонажей, создание имени и внешности, оригинальные анимированные
модели обоих полов, удаление с подтверждением и сетевой переход на shard.
Завершение загрузки мира отправляется отдельным `CompleteLoadingAsync`.
Основной мир подключён к сетевому переходу: карта 0 загружается в серверной
позиции, подтверждение loading отправляется после подготовки ресурсов.
После сохранения tutorial используется новый authoritative snapshot RustyFusion.
Движение, прыжок и остановка отправляют MOVE/JUMP/STOP; GOTO меняет позицию
по серверу. Неимпортированные карты/instances и координаты вне покрытия
отклоняются. Существующий tutorial имеет отдельную локальную постановку.
Сетевая репликация других игроков/NPC, обычный бой, инвентарь, задания,
Nano, торговля и остальные игровые сервисы ещё не перенесены целиком.

Экран входа следует текущему FFOneClient: справа список серверов со статусами,
обновлением и добавлением адреса; в форме — «Запомнить» и список сохранённых
аккаунтов выбранного сервера. По умолчанию выбран `localhost:23000`, а список
содержит SlavicFall. HTTPS-адрес использует ofapi, `host:port` — прямой вход,
который требует разрешённого сервером входа по паролю. Кнопки «+», карандаш и
назад переключают создание/редактирование учётной записи и список аккаунтов.

После успешного входа «Запомнить» сохраняет пароль прямого подключения или
refresh-токен ofapi в Windows Credential Manager. JSON содержит только серверы
и имена аккаунтов. У Unity отдельные профили в `Application.persistentDataPath`
и отдельное пространство секретов `FFOneUnity`; существующие профили Rust
автоматически не импортируются. Сохранённые аккаунты пока поддержаны на Windows.
Язык EN/RU переключается на экране входа. В настройках язык текста и озвучки
выбираются независимо; tutorial использует отдельный выбор голосов.

## Редактирование

Полная публикация контента выполняется по этапам через **FFOne → Content**:
**Import Complete FFOneClient Set**, **Prepare Imported Model Dependencies**,
**Publish All Structured Data**,
**Publish All Models**, **Bind Published Models to Existing Content**,
**Build Complete Lazy Catalog**, **Validate Complete Publication**.
Проверка сравнивает с исходником каждый документ, тип Unity asset и зависимости
каждого prefab. После намеренных правок данных отличие от источника будет
отмечено проверкой; сами правки сохраняются. Этапы допускают повторный запуск: уже
опубликованные пользовательские изменения не заменяются исходниками.

**All Native Assets and Data** открывает поиск по семантическим путям всего
набора. Каталог содержит строки путей, а не ссылки на загруженные модели.
Есть фильтр по типу и постраничный просмотр без ограничения первыми 200 строками.
Выбор строки открывает соответствующий Unity asset.

JSON публикуются как `NativeDataDocument` в
`Assets/Resources/NativeData/<исходный путь>.json.asset`. Например, таблицы
находятся в `NativeData/data/tables/xdt.json.asset`, а переводы — в
`NativeData/localization/en.json.asset` и `ru.json.asset`. Inspector показывает
типизированные поля и позволяет искать ключи/значения, переходить в объекты и
массивы, менять значения с Undo и выбирать связанные Unity assets.
Сохраняются все поля, порядок строк и ключей, null/bool/string и исходная запись
чисел: 64-битные ID и точные десятичные значения не округляются до Unity float.
Строки с пробелами, управляющими символами и UTF-16 surrogate-парами имеют
дополнительное точное представление: это защищает двойные пробелы и CR/LF
от сворачивания строк в YAML-сериализаторе Unity. Inspector и runtime читают
восстановленное значение; читаемый текст также остаётся в asset.
Окно **FFOne → Localization EN-RU** после публикации редактирует эти assets.
Для изменения структуры произвольного документа доступны **Export JSON…** и
**Import JSON…** в Inspector: импорт проверяет JSON, поддерживает Undo и сохраняет
GUID существующего asset. Экспорт сохраняет точные числовые токены и значения.

Код читает документы через `NativeData.Object/Read/Load`; `NativeContentCatalog`
разрешает прямые и относительные ссылки по исходным идентичностям. PNG/OGG/шрифты
имеют обычные Unity import settings; BIN дополнительно доступны как TextAsset
`.bytes` в `NativeBinary`, два WGSL-файла — как исходный текст в
`NativeShaderSources`. WGSL не исполняется Unity: модели используют существующие
URP-шейдеры проекта. Метаданные повторной публикации находятся в `Assets/Editor`,
в runtime-каталоги они не входят. Исходный FFOneClient не изменяется.
Рабочее пространство редактора из `assets/editor/world-workspace.json` хранится
отдельно в `Assets/Editor/FFOneClientData/world-workspace.json.asset`, чтобы
локальные пути рабочего пространства не попадали в runtime-данные.
Исторические пути mip-текстур из `objects/legacy-static-exact-mips.json`
разрешаются в существующие текстуры по 25 подтверждённым SHA-256-соответствиям;
документ и сами текстуры не переписываются. Эти связи сохраняются в
`Assets/Editor/NativePublications/VerifiedContentAliases.json`.
Сверка полного исходного набора записана в `Logs/CompleteSourceIntegrity.json`:
73 906 файлов, 0 пропусков, 0 неожиданных отличий SHA-256. Два прежних raw JSON
локализации сохранены; нативные документы EN/RU содержат полный источник
FFOneClient — по 68 960 ключей. `Logs/CompleteSourceReferenceAudit.json` отдельно
фиксирует старые пути в метаданных происхождения, не изменяя эти метаданные.

- **FFOne → Content Import**: предварительная проверка и перенос зависимостей
  из `../FFOneClient/assets/game`. Исходники остаются неизменными; конфликт
  с правкой внутри Unity останавливает импорт до записи. Повторный импорт
  не переписывает совпадающие файлы.
- **FFOne → Localization EN-RU**: правка обоих языков с проверкой placeholders
  и внешних изменений. После публикации переводы читаются из нативных документов;
  переоткройте экран для обновления подписей.
- **FFOne → Frontend Layout**: смещения и размеры именованных элементов
  login/selection, сохранение и просмотр в Play Mode, возврат к оригиналу.
- GLB импортируются в Unity mesh/material/skinned-renderer/animation subassets.
  Базовые файлы, PNG, OGG, шрифты и JSON находятся в
  `Assets/Resources/`. GLB остаются исходниками импорта. **FFOne → Content →
  Publish Player And Tutorial Models** публикует самостоятельные prefab,
  mesh, material и animation assets в `Assets/Resources/NativeEditable`,
  сохраняя семантические пути. Выбор GLB/папки в Project также поддерживает
  **Assets → FFOne → Preflight/Publish Selected Native Models**.
  Весь набор проходит preflight до первой записи. Повторная публикация
  сохраняет правки; изменение источника, потеря GUID или конфликт останавливают её.
  Provenance находится только в `Assets/Editor/NativePublications`.
  Runtime предпочитает опубликованные prefab при загрузке персонажей,
  tutorial actors/effects и world placements. Animator персонажа использует
  отдельные редактируемые Mecanim clips/controllers, описанные ниже.
  Шейдер `FFOne/NativeToon` работает
  в URP; аватары используют исходную toon-ramp и порядок слоёв лица,
  отдельная комиксная ветка сохранена для мира. Превью соответствует физическому
  размеру элемента UI и использует MSAA 4×.

Персонажи используют редактируемые Animator Controller в
`Assets/Resources/characters/player/shared/animation`: все 127 клипов каждого пола,
исходные режимы loop/clamp, переходы действий, маску верхней части тела и отдельные
аддитивные слои роста/телосложения. **FFOne → Animation → Rebuild Player Controllers**
обновляет их из принятых импортированных клипов. Смена внешности того же пола
сохраняет скелет и время анимации; камеры удерживают RenderTexture при колебаниях UI.

Импорт интерфейса включает одежду конструктора, исходную графику этих экранов,
локализацию и зависимости; основной мир имеет отдельный импорт. Идентификаторы, варианты, исходные каталоги и
согласованные шрифты сохраняются. Для персонажа в ещё не перенесённой одежде
клиент сообщает об отсутствующей зависимости; внешность не подменяется.

Экран входа следует FFOneClient, включая серверы и сохранённые аккаунты.
Выбор персонажа, создание имени и внешности следуют оригинальному Retrobution
20260821: исходные прямоугольники, состояния контролов и масштаб `height / 681`.
Колесо имени прокручивается при удержании стрелки, палитры используют исходные
страницы и графические стрелки. Переводы EN/RU подгоняются внутри контролов;
согласованные replacement-шрифты сохранены. Попиксельное совпадение шрифтов
и освещения с работающим старым клиентом ещё не подтверждено.

## Настройки и игровой переход

`Assets/Resources/ui/views/Settings.uxml` и `ui/styles/Settings.uss` редактируются
в UI Builder. Четыре вкладки используют перенесённую графику OptionMode.
Окно открывается через F10; в обычном мире также действует назначение `Option`.
Текст и голоса EN/RU независимы. Сохранение, отмена, предварительное применение
звука, перехват назначений и конфликты клавиш реализованы отдельно от layout.
Preferences находятся в `unity-options.json` в persistentDataPath;
повреждённый файл не перезаписывается.

Подключены общая громкость, основные аудиоканалы tutorial, язык/голоса,
разрешение/windowed, качество текстур, anisotropic filtering и назначения
движения/прыжка/поворота в обычном мире. Часть controls пока только сохраняет
значения: остальные graphics/display/social эффекты, legacy pad profiles и
клавиши ещё отсутствующих игровых сервисов требуют runtime adapters.
Не следует считать сохранение значения доказательством работающего эффекта.

Escape в обычном мире открывает `WorldMenu.uxml`; смена персонажа и выход
ожидают подтверждение сохранения RustyFusion. Нет локального присвоения
прогресса, NPC, инвентаря или результатов боёв.

## Просмотр основного мира и сравнение

**FFOne → World → Open Native World** открывает `Assets/Scenes/NativeWorld.unity`.
**Build World Comparison Player** собирает отдельный просмотрщик
`Builds/WorldBenchmark/Player/FFOneWorld.exe`. Для переноса нужна вся папка Player.
Он работает без сервера: WASD - движение, Q/E - высота, Shift - ускорение,
правая кнопка мыши - обзор, F8 - следующая область. Переходы загружают и
выгружают чанки с пределом девять корней и расстояниями 356/420 единиц.

**Import Entire Native World** переносит принятые зависимости из FFOneClient;
**Retry Incomplete Import** продолжает незавершённую подготовку. Импортированы
170 тайлов, рельеф, трава, размещения моделей и коллайдеров, кривые анимации,
движущиеся части, частицы и опубликованные эффекты. Записи без исходных
привязок отражаются в `sourceCoverageNotes`; они не считаются восстановленными.

`Tools/run_world_benchmark.ps1` запускает три камеры последовательно, меняет
порядок baseline/shared между повторами и измеряет переход на 512 единиц.
Параметр `-CapturePoses` сохраняет состояния t=0/t=1 отдельно от FPS;
`-Backend vulkan` выбирает общий API для сравнения с Rust. Не запускайте два
стенда одновременно. Замеры с фоновой компиляцией и аварийным завершением
исключаются; файловый кэш ОС не сбрасывается. Режим shared сохраняет общие
материалы и SRP batching, baseline отключает эти оптимизации.

## Исходники и проверки

`Assets/Scripts/Runtime/Network` — самостоятельный протокол 0104;
`UI` — frontend/settings; `Creation` — конструктор; `Content` — каталоги и
сборка моделей; `Integration` — камеры предпросмотра.
`Assets/Scripts/Editor` — импорт и окна редактирования.
`Assets/Tests/Editor` — scoped Unity EditMode tests.

Проверки сети используют loopback fixtures. Проверять создание/удаление на
живом RustyFusion следует с отдельной SQLite-базой и отдельными портами.
Уже настроенная сцена включена в Build Profiles; стандартная сборка Unity
создаёт самостоятельный клиент без зависимости от соседних репозиториев.
